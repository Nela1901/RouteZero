## 1. Evaluación de Alternativas de Stack Tecnológico

| Criterio de Evaluación | Alternativa 1: MERN (Node/Express + React + MongoDB) | Alternativa 2: Python + FastAPI + React + PostgreSQL | Alternativa 3: Java Spring Boot + Angular + PostgreSQL |
|---|---|---|---|
| **Curva de aprendizaje** | Baja (JavaScript unificado en frontend y backend) | Media (Python backend, JavaScript frontend) | Alta (Verboso, fuertemente tipado, configuración compleja) |

| **Alineación con la consigna del proyecto** | Media (MongoDB no es base de datos relacional requerida) | Alta (cumple todos los requisitos tecnológicos de la consigna) | Baja (Angular y Java no están en la consigna) |

## 2. Stack Tecnológico Seleccionado

La Alternativa 2 obtuvo el puntaje más alto (9.2/10) en la evaluación multidimensional, siendo la única que cumple simultáneamente todos los criterios críticos del proyecto.

## 4. Justificación Técnica Formal

### 4.1 Frontend — React.js 18+

React.js fue seleccionado sobre Vue.js y Angular por las siguientes razones:

- **Ecosistema**: Mayor cantidad de librerías compatibles con Leaflet para visualización de mapas interactivos
- **Componentes reutilizables**: Arquitectura basada en componentes facilita el desarrollo del dashboard, mapa y módulos de gestión
- **Comunidad**: La comunidad más grande del ecosistema frontend, con mayor disponibilidad de recursos en español para el equipo
- **Demanda laboral**: Tecnología con mayor demanda en el mercado peruano, aportando valor al portafolio del equipo

### 4.2 Backend — Python 3.11+ + FastAPI 0.100+

FastAPI fue seleccionado sobre Django y Node/Express por:

- **Integración nativa con Python**: El algoritmo ACO (Colonia de Hormigas) y GA (Algoritmo Genético) se implementan en Python, eliminando la necesidad de servicios adicionales de comunicación entre capas
- **Rendimiento**: FastAPI es uno de los frameworks web más rápidos disponibles en Python, comparable con Node.js y Go en benchmarks estándar
- **Documentación automática**: Genera Swagger/OpenAPI automáticamente en `/docs`, cumpliendo el requisito de documentación de API de la consigna
- **Tipado estático**: El uso de Pydantic para validación de datos reduce errores en tiempo de ejecución
- **Eficiencia energética**: Menor consumo de CPU y RAM respecto a Django y Spring Boot, alineado con los principios Green Software

### 4.3 Base de datos — PostgreSQL 15+

PostgreSQL fue seleccionado sobre MongoDB y MySQL por:

- **Modelo relacional**: La naturaleza del proyecto (flota, pedidos, conductores, rutas) se modela naturalmente con relaciones entre entidades
- **Soporte geoespacial**: Extensión PostGIS para manejo nativo de coordenadas GPS y datos georreferenciados del distrito de Huancayo
- **Confiabilidad**: ACID compliance garantiza integridad de datos en operaciones críticas de optimización de rutas
- **Open source**: Sin costos de licenciamiento, alineado con el presupuesto académico del proyecto

### 4.4 Mapas — Leaflet + OpenStreetMap

- **Costo cero**: Sin límites de uso ni costos por API calls, a diferencia de Google Maps API
- **Datos precisos**: OpenStreetMap tiene buena cobertura del distrito de Huancayo y el Parque Industrial de El Tambo
- **Integración con React**: react-leaflet ofrece componentes nativos para React con soporte activo

### 4.5 Algoritmo — ACO (Colonia de Hormigas) + GA (Algoritmo Genético)

- **ACO como algoritmo principal**: Natural para problemas de rutas múltiples (VRPTW), intuitivo de explicar en la sustentación y con buena convergencia para el tamaño del problema (150 pedidos, 15 vehículos)
- **GA como algoritmo secundario**: Se implementa en la Iteración 4 como mejora o comparación de resultados con ACO

### 4.6 Despliegue — Render + Vercel

- **Render**: Despliegue del backend FastAPI y la base de datos PostgreSQL en plan gratuito, con URL pública estable para la sustentación
- **Vercel**: Despliegue del frontend React.js en plan gratuito, con URL pública y dominio personalizado para la sustentación
